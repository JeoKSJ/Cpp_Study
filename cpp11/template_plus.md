## 먼저 "컴파일은 파일 하나씩 따로 한다"는 사실부터

이 부분이 어려운 이유는 **컴파일 구조**를 알아야 이해되기 때문이에요. 핵심 사실 하나만 먼저 잡고 갈게요.

> C++ 컴파일러는 `.cpp` 파일을 **하나씩 따로따로** 컴파일합니다. 컴파일 중에는 **다른 `.cpp`의 내용을 볼 수 없어요.**

```
main.cpp  ──컴파일──▶  main.o      (기계어 조각)
Person.cpp ─컴파일──▶  Person.o    (기계어 조각)
                         │
              링크(합치기) ▼
                     myprogram
```

링크는 `.o`들을 **이어 붙이는** 단계라, 이미 기계어가 된 함수들을 서로 연결해줄 뿐이에요.

## 일반 함수는 어떻게 되나

`add`를 나눈 경우를 따라가볼게요.

```cpp
// math_utils.h
int add(int a, int b);        // 선언

// math_utils.cpp
int add(int a, int b) { return a + b; }   // 정의

// main.cpp
#include "math_utils.h"
int main() { add(3, 4); }
```

1. **`math_utils.cpp` 컴파일**: `add`의 몸체가 보이므로 **진짜 기계어 `add`가 `math_utils.o`에 생성**됩니다
2. **`main.cpp` 컴파일**: 선언만 보여요. 컴파일러는 "`add(int,int)`라는 게 어딘가에 있겠지" 하고 **"여기서 add를 호출한다"는 메모만 남기고** 넘어갑니다
3. **링크**: 그 메모를 `math_utils.o`의 진짜 `add`와 이어줍니다

선언만 알아도 되는 이유는, `add`가 **이미 완성된 기계어**로 존재하기 때문이에요. 연결만 하면 됩니다.

## 템플릿은 왜 다른가

템플릿은 **함수가 아니라 틀**이라고 했죠. `T`가 뭔지 모르면 기계어를 만들 수가 없어요. `int`일 때와 `double`일 때 필요한 기계 명령이 다르거든요(정수 덧셈과 실수 덧셈은 다른 명령입니다).

그래서 `template <typename T> T maxOf(T a, T b)`는 `.cpp`에서 컴파일해도 **기계어가 아예 만들어지지 않습니다.** 어떤 `T`가 필요한지 아직 모르니까요.

`T`가 정해지는 순간은 **사용하는 쪽**이에요.

```cpp
maxOf(3, 7);   // 이 순간 T = int 가 정해짐 → int용 maxOf를 이 자리에서 찍어내야 함
```

찍어내려면 틀의 **몸체(`return (a > b) ? a : b;`)를 읽어야** 하고, 그 작업은 `maxOf(3, 7)`를 컴파일하는 **그 파일(main.cpp) 안에서** 일어나요.

## 몸체를 `.cpp`에 숨기면 생기는 일

```cpp
// maxof.h
template <typename T>
T maxOf(T a, T b);            // 선언만

// maxof.cpp
#include "maxof.h"
template <typename T>
T maxOf(T a, T b) { return (a > b) ? a : b; }   // 몸체는 여기에

// main.cpp
#include "maxof.h"
int main() { maxOf(3, 7); }
```

시간 순서로 따라가보면:

1. **`maxof.cpp` 컴파일**: 몸체는 보이지만, 이 파일 안에서 `maxOf`를 **아무도 호출하지 않아요.** `T`가 뭔지 모르니 **기계어를 하나도 안 만듭니다**
2. **`main.cpp` 컴파일**: `maxOf<int>`가 필요하다는 걸 알지만 **몸체가 안 보여요.** 찍어낼 수 없으니 일반 함수처럼 **"링크 때 연결해주겠지" 메모만 남깁니다**
3. **링크**: `main.o`가 `maxOf<int>`를 찾는데, `maxof.o` 어디에도 없어요 → **`undefined reference to maxOf<int>(int, int)`**

```
main.cpp:    "maxOf<int> 필요한데 몸체가 안 보임... 링크가 찾아주겠지"
maxof.cpp:   "나는 T가 뭔지 모르니 아무것도 안 만들었음"
링크:         "어디에도 없는데요?" → 에러
```

**서로 상대가 해줄 거라고 믿다가 아무도 안 만든 상황**이에요.

## 그래서 헤더에 몸체까지 넣는다

```cpp
// maxof.h
#pragma once

template <typename T>
T maxOf(T a, T b) { return (a > b) ? a : b; }   // 몸체까지 헤더에
```

`main.cpp`가 `#include "maxof.h"`를 하면 **헤더 내용이 main.cpp에 복사**되기 때문에, 컴파일 중에 몸체가 보이고 `maxOf<int>`를 **그 자리에서 직접 만들 수** 있습니다. (4번 항목에서 말한 "include = 복사 붙여넣기"가 여기서 의미를 가져요.)

## 표로 비교

| | 일반 함수 | 템플릿 |
|---|---|---|
| 정체 | 완성된 함수 | 함수를 찍어내는 틀 |
| `.cpp` 컴파일 시 | 기계어 생성됨 | **아무것도 안 만들어짐** |
| 사용하는 쪽에서 필요한 것 | 선언만 | **몸체 전체** |
| 헤더에 넣는 것 | 선언 | **선언 + 몸체** |

## 보충: 같은 틀이 여러 파일에서 만들어지면?

`a.cpp`와 `b.cpp`가 둘 다 `maxOf<int>`를 찍어내면 같은 함수가 두 개 생길 것 같지만, 템플릿으로 만든 건 **링커가 중복을 알아서 하나로 합쳐줍니다.** 그래서 9번의 `multiple definition` 에러가 템플릿에는 나지 않아요.

## 예외: 몸체를 `.cpp`에 두는 방법도 있긴 해요

`.cpp` 끝에 `template int maxOf<int>(int, int);`처럼 **필요한 타입을 미리 명시적으로 찍어두면** 가능합니다. 하지만 쓸 타입을 전부 미리 적어야 해서 불편하고 실무에서도 드물어요. 지금은 **"템플릿은 몸체까지 헤더"**만 기억하세요.

## 📌 핵심 한 줄 정리

1. 컴파일러는 `.cpp`를 **하나씩 따로** 컴파일하고, 링크가 결과물을 이어 붙인다
2. 일반 함수는 `.cpp`에서 **기계어가 완성**되어 있어서 선언만 알면 호출 가능하다
3. 템플릿은 `T`가 정해지는 **사용하는 쪽에서** 기계어를 찍어내므로, 그 파일에서 **몸체가 보여야** 한다
4. 몸체가 `.cpp`에 있으면 아무도 만들지 않아 **`undefined reference`** 링크 에러가 난다

"일반 함수는 미리 만들어져 있고, 템플릿은 주문이 들어와야 만든다"는 비유로 기억하시면 편해요. 주문서(사용하는 파일)에 **레시피(몸체)**가 같이 붙어 있어야 만들 수 있는 거죠.
