## 1. 메모리의 두 영역: 스택과 힙

| | 스택(stack) | 힙(heap) |
|---|---|---|
| 만드는 법 | `int x = 10;` 같은 일반 변수 | `new`로 직접 요청 |
| 정리 | **자동** (블록이 끝나면 사라짐) | **직접** `delete` 해야 함 |
| 크기/수명 | 작고 블록 안에서만 | 크고 내가 정한 만큼 |

지금까지 대부분의 변수는 스택에 있어서 신경 쓸 게 없었어요. 문제는 **힙**입니다. 객체를 함수 밖까지 살려야 하거나, 다형성(8강)처럼 `Animal*`로 다루려면 힙이 필요해요.

## 2. new / delete 기본

```cpp
int* p = new int(10);     // 힙에 int를 만들고 그 주소를 받음
cout << *p << endl;       // 10
delete p;                 // 다 썼으니 직접 반납 (필수!)

int* arr = new int[5];    // 배열은 new[]
delete[] arr;             // 배열은 delete[] (대괄호 필수)
```

규칙은 **`new`로 만들면 반드시 `delete`로 지운다**, 그리고 **`new[]`는 `delete[]`**예요.

## 3. 손으로 관리하면 생기는 문제들

**① 메모리 누수 (memory leak)**: `delete`를 잊음

```cpp
void f() {
    int* p = new int(10);
    // delete를 안 함 → 함수가 끝나도 힙 메모리는 계속 점유됨
}
```

**② 예외로 건너뛰기** (14강 연결): 중간에 예외가 나면 `delete`까지 도달하지 못함

```cpp
void g() {
    Animal* a = new Dog("초코");
    mayThrow();       // 여기서 예외 발생하면?
    delete a;         // 실행 안 됨 → 누수
}
```

**③ 이중 해제 (double delete)**: 같은 걸 두 번 지움 → 프로그램이 죽을 수 있음

```cpp
delete p;
delete p;     // 위험!
```

**④ 댕글링 포인터 (dangling pointer)**: 지운 뒤에 그 주소를 계속 씀

```cpp
delete p;
cout << *p;   // 위험! 이미 반납한 메모리
```

공통 원인은 **"누가 지울지 사람이 기억해야 해서"**예요. 이걸 자동화하는 게 스마트 포인터입니다.

## 4. RAII: 자원은 객체가 책임진다

14강 7번에서 본 **스택 되감기**를 떠올려보세요. 예외가 나도 지역 객체의 **소멸자는 반드시 호출**됐죠. 이걸 이용하는 설계 원칙이 **RAII**(자원 획득은 초기화, "Resource Acquisition Is Initialization")입니다.

```
생성자에서 자원을 얻고 → 소멸자에서 자원을 반납
→ 객체가 사라지면 자원도 자동으로 정리됨
```

스마트 포인터는 **"포인터를 들고 있다가, 자기가 사라질 때 `delete`를 대신 호출해주는 객체"**예요. 7강에서 "소멸자가 나중에 중요해진다"고 했던 약속이 바로 이거예요.

```cpp
#include <memory>    // 스마트 포인터 헤더
```

## 5. unique_ptr: 혼자 소유하는 포인터 (기본 선택)

```cpp
#include <memory>

auto p = make_unique<int>(10);       // new int(10)과 같지만 delete 불필요
cout << *p << endl;                  // 10 (일반 포인터처럼 * 사용)
// 블록이 끝나면 자동으로 delete 됨!
```

클래스도 똑같아요.

```cpp
auto a = make_unique<Dog>("초코");
a->makeSound();                      // -> 도 일반 포인터처럼 사용
// 예외가 나도, 함수가 끝나도 자동 정리됨
```

- `make_unique<타입>(생성자 인자)`로 만들어요 (`new` 대신)
- `*`, `->`를 **일반 포인터와 똑같이** 쓸 수 있어요 (4강, 8강 문법)
- 스코프를 벗어나면 소멸자가 `delete`를 호출합니다 → **누수, 예외 문제 해결**

### "혼자 소유"의 의미: 복사 금지

```cpp
auto a = make_unique<int>(5);
// auto b = a;            // 에러! unique_ptr은 복사할 수 없음
auto b = std::move(a);    // 소유권을 b에게 "넘김" (이동)
// 이제 a는 비어 있고(nullptr), b가 소유함
```

한 객체의 주인은 **딱 하나**라서, 복사 대신 **소유권 이전(`move`)** 만 허용돼요. 덕분에 "누가 지울지"가 항상 명확해져 ③이중 해제 문제도 막혀요. `std::move`는 지금은 "소유권을 넘기는 문법"이라고만 알아두세요(깊은 내용은 이동 의미론이라는 별도 주제예요).

### 함수에 넘길 때

```cpp
void use(const Dog& d) { }        // 소유권이 필요 없으면: 참조로 받기 (권장)
use(*a);                          // *a는 가리키는 객체 자체

void take(unique_ptr<Dog> d) { }  // 소유권을 넘길 때만
take(std::move(a));
```

대부분은 **참조로 받으면 충분**하고, 소유권을 넘길 때만 `unique_ptr`째로 넘겨요.

## 6. shared_ptr: 여럿이 공유하는 포인터

```cpp
auto a = make_shared<int>(10);
auto b = a;                              // 복사 가능! 둘이 같은 걸 가리킴
cout << a.use_count() << endl;           // 2 (소유자 수)

b.reset();                               // b가 손을 뗌
cout << a.use_count() << endl;           // 1
// 마지막 소유자가 사라지면 그때 자동으로 delete
```

- **참조 횟수(reference count)** 방식: 소유자가 몇 명인지 세다가, **0이 되는 순간** 지웁니다
- `use_count()`로 현재 소유자 수 확인
- 여러 곳에서 같은 객체를 써야 하고 **누가 마지막인지 모를 때** 사용해요

```
a ──┐
    ├──▶ [int 10]  (소유자 2명)
b ──┘
```

### ⚠️ 순환 참조 주의

두 객체가 서로를 `shared_ptr`로 붙잡으면 소유자 수가 영원히 0이 안 돼서 **누수**가 생겨요. 이럴 때 **`weak_ptr`**(소유권 없이 관찰만 하는 포인터)로 한쪽을 끊습니다. 지금은 "이런 함정과 해결책이 있다"만 알아두세요.

## 7. 무엇을 써야 하나

| 상황 | 선택 |
|---|---|
| 기본 | **`unique_ptr`** (가볍고 소유자가 명확함) |
| 여러 곳이 공유해야 할 때만 | `shared_ptr` |
| 소유권 없이 빌려 쓰기만 | **일반 참조(`&`)나 일반 포인터** (소유하지 않으니 `delete` 안 함) |
| 순환 참조를 끊고 싶을 때 | `weak_ptr` |
| 직접 `new`/`delete` | 거의 쓰지 않음 |

**"`unique_ptr`부터 생각하고, 정말 공유가 필요할 때만 `shared_ptr`"** 이 원칙이에요. 현대 C++에서는 코드에 `new`와 `delete`를 직접 쓰는 일이 드뭅니다.

## 8. 8강 코드 되돌아보기: vector<Animal*> 개선

8강에서 이렇게 썼죠.

```cpp
vector<Animal*> animals;
animals.push_back(new Dog("초코"));
animals.push_back(new Cat("나비"));
// ...
for (Animal* a : animals) delete a;     // 직접 delete 해야 했음
```

스마트 포인터로 바꾸면 `delete` 반복문이 사라집니다.

```cpp
vector<unique_ptr<Animal>> animals;
animals.push_back(make_unique<Dog>("초코"));
animals.push_back(make_unique<Cat>("나비"));

for (const auto& a : animals) {
    a->makeSound();      // 다형성 그대로 동작
}
// vector가 사라질 때 각 unique_ptr이 알아서 delete
```

- `const auto&`는 13강에서 본 "복사 없이 읽기만" 관용구예요. `unique_ptr`은 **복사가 금지**라 `for (auto a : animals)`로 쓰면 복사 에러가 나서 **반드시 `&`가 필요**합니다
- 8강 6번의 **가상 소멸자**(`virtual ~Animal()`)는 여전히 필요해요. `Animal*` 타입으로 지워질 때 `Dog`의 소멸자까지 호출되게 하는 장치입니다

## 9. 알아두면 좋은 안전 습관

1. **`new`로 시작하는 일반 포인터는 가능하면 쓰지 않는다** → `make_unique`/`make_shared`
2. 포인터를 쓰기 전에는 `nullptr`인지 확인 (4강)
3. 소유하지 않는 곳은 **일반 참조/포인터로 빌려 쓰고 `delete` 하지 않는다**
4. `new[]`로 만들 일이 생기면 대신 **`vector`를 쓴다** (13강 이전의 보충). `vector`가 내부적으로 메모리를 알아서 관리해서 `new[]`/`delete[]`가 필요 없어요
5. 지금 `vector<int>`, `string`을 쓰는 것 자체가 이미 RAII예요. 그들도 소멸자에서 메모리를 정리합니다

## 📌 15강 요약

1. 일반 변수는 **스택**(자동 정리), `new`로 만든 것은 **힙**(직접 `delete`)에 있다.
2. 직접 관리하면 **누수, 예외로 건너뛴 `delete`, 이중 해제, 댕글링 포인터** 문제가 생긴다.
3. **RAII**: 생성자에서 자원을 얻고 소멸자에서 반납한다. 예외가 나도 소멸자는 호출되므로 안전하다.
4. **`unique_ptr`**은 혼자 소유하며 복사는 금지, `std::move`로 소유권을 넘긴다. `make_unique`로 만들고 `*`, `->`는 일반 포인터처럼 쓴다. **기본 선택이다.**
5. **`shared_ptr`**은 참조 횟수를 세어 마지막 소유자가 사라질 때 지운다. 순환 참조는 `weak_ptr`로 끊는다.
6. 소유하지 않고 빌려 쓰기만 하면 **참조(`&`)나 일반 포인터**를 쓰고 `delete`하지 않는다.
7. 현대 C++에서는 `new`/`delete`를 직접 쓰지 않고, **`vector`, `string`, 스마트 포인터**에 맡긴다.
