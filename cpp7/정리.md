## 1. 생성자(Constructor)란?

지금까지는 객체를 만든 뒤 매번 `p1.name = "철수"; p1.age = 25;`처럼 멤버 변수를 하나씩 따로 설정했어요. **생성자**를 쓰면 객체가 만들어지는 순간 자동으로 초기값을 설정할 수 있습니다.

```cpp
class Person {
public:
    std::string name;
    int age;

    // 생성자: 클래스 이름과 똑같고, 반환 타입이 없음
    Person(std::string n, int a) {
        name = n;
        age = a;
    }

    void introduce() {
        std::cout << name << " (" << age << "세)" << std::endl;
    }
};

int main() {
    Person p1("철수", 25);   // 객체 생성과 동시에 초기화!
    p1.introduce();          // 철수 (25세)
    return 0;
}
```

생성자의 특징:

- **이름이 클래스 이름과 완전히 같아야** 합니다 (`Person` 클래스 → `Person()` 생성자).
- **반환 타입이 없습니다** (`void`도 안 붙임).
- 객체(`p1`)가 만들어지는 순간, 자동으로 딱 한 번 호출됩니다.

## 2. 생성자도 오버로딩 가능

3강에서 배운 함수 오버로딩처럼, 생성자도 여러 개 만들어서 다양한 방식으로 객체를 만들 수 있습니다.

```cpp
class Person {
public:
    std::string name;
    int age;

    Person() {                  // 매개변수 없는 생성자 (기본 생성자)
        name = "이름없음";
        age = 0;
    }

    Person(std::string n, int a) {   // 매개변수 있는 생성자
        name = n;
        age = a;
    }
};

int main() {
    Person p1;                 // 기본 생성자 호출 → "이름없음", 0세
    Person p2("영희", 23);     // 매개변수 있는 생성자 호출

    p1.introduce();
    p2.introduce();
    return 0;
}
```

⚠️ 참고로 생성자를 하나도 안 만들면, 컴파일러가 **아무 일도 안 하는 기본 생성자**를 자동으로 만들어줍니다. 하지만 생성자를 하나라도 직접 만들면, 그때부턴 매개변수 없는 기본 생성자가 자동으로 생기지 않으니 필요하면 직접 만들어야 합니다.

## 3. 멤버 초기화 리스트

생성자 본문(`{}`)에서 대입하는 대신, 좀 더 C++스러운 방식으로 멤버를 초기화할 수 있습니다.

```cpp
class Person {
public:
    std::string name;
    int age;

    Person(std::string n, int a) : name(n), age(a) {   // 콜론(:) 뒤에 초기화 리스트
        // 본문은 비어있어도 됨
    }
};
```

`: name(n), age(a)`는 "멤버 변수 `name`을 `n`으로, `age`를 `a`로 **초기화**하라"는 뜻이에요. 본문 안에서 `name = n;`처럼 **대입**하는 것과 결과는 비슷해 보이지만, 엄밀히는 "처음부터 그 값으로 만드는 것"과 "일단 만들고 나중에 값을 바꾸는 것"의 차이가 있습니다. 지금은 "생성자에서는 이 방식을 많이 쓴다" 정도로 익숙해지시면 충분하고, `const` 멤버 변수처럼 반드시 이 방식을 써야만 하는 경우도 나중에 만나게 될 거예요.

## 4. this 포인터

멤버 함수 안에서 매개변수 이름과 멤버 변수 이름이 같으면 어떻게 될까요?

```cpp
class Person {
public:
    std::string name;

    void setName(std::string name) {   // 매개변수 이름도 name!
        name = name;    // 문제: 어느 쪽 name을 말하는 걸까?
    }
};
```

이 경우 `name = name;`은 매개변수가 자기 자신에게 대입하는 꼴이 되어서, **멤버 변수 `name`은 전혀 바뀌지 않습니다.** 이럴 때 **`this` 포인터**를 씁니다.

```cpp
class Person {
public:
    std::string name;

    void setName(std::string name) {
        this->name = name;   // this->name은 "이 객체의" 멤버 변수 name
    }
};
```

- `this`는 **"현재 이 멤버 함수를 호출한 객체 자신을 가리키는 포인터"**입니다. 4강에서 배운 포인터 개념이 여기서 등장하죠.
- `this->name`은 "이 객체의 `name` 멤버"라는 뜻이고, `name`(매개변수)과 명확히 구분됩니다.
- `p1.setName("철수")`라고 호출하면, 그 함수 안에서 `this`는 `p1`의 주소를 가리키게 됩니다.

> 💡 실무에서는 이런 이름 충돌을 피하려고 멤버 변수 이름 앞에 밑줄을 붙이거나(`_name`, `m_name`처럼) 관례를 정해두는 경우도 많아요. 그러면 `this->`를 꼭 안 써도 구분이 되니까요. 하지만 `this`가 뭔지 아는 건 중요합니다.

## 5. 소멸자(Destructor)

객체가 **수명을 다하고 사라질 때** 자동으로 호출되는 함수입니다. 지난 질문에서 말씀드렸던 바로 그 부분이에요.

```cpp
class Person {
public:
    std::string name;

    Person(std::string n) : name(n) {
        std::cout << name << " 생성됨" << std::endl;
    }

    ~Person() {   // 소멸자: 클래스 이름 앞에 ~ 를 붙임
        std::cout << name << " 소멸됨" << std::endl;
    }
};

int main() {
    Person p1("철수");
    std::cout << "프로그램 실행 중..." << std::endl;
    return 0;
}
// 출력:
// 철수 생성됨
// 프로그램 실행 중...
// 철수 소멸됨   <- main 함수가 끝나면서 p1이 자동으로 소멸됨
```

소멸자의 특징:

- 이름은 `~클래스이름` (물결표 + 클래스 이름)
- 매개변수도 없고, 오버로딩도 불가능합니다 (클래스당 소멸자는 딱 1개).
- `p1`처럼 지역 변수로 만든 객체는 그 객체가 선언된 `{}` 블록(여기서는 `main` 함수)을 벗어나는 순간 **자동으로** 소멸자가 호출됩니다. 직접 호출할 일은 거의 없습니다.

지금 당장은 소멸자가 별로 할 일이 없어 보이지만, 나중에 객체가 동적으로 할당한 메모리(예: `new`로 만든 것)를 정리하는 역할을 배우게 되면 왜 필요한지 확실히 와닿을 거예요.

## 📌 오늘의 요약

1. **생성자**는 클래스 이름과 같고 반환 타입이 없는 함수로, 객체가 만들어질 때 자동으로 호출되어 초기화를 담당한다.
2. 생성자는 함수처럼 **오버로딩**이 가능하며, 생성자를 하나라도 직접 만들면 자동 기본 생성자는 더 이상 제공되지 않는다.
3. `: 멤버(값), 멤버(값)` 형태의 **멤버 초기화 리스트**로 생성자에서 멤버를 초기화할 수 있다.
4. **`this`**는 현재 객체 자신을 가리키는 포인터로, 매개변수와 멤버 변수 이름이 겹칠 때 `this->멤버`로 구분한다.
5. **소멸자**(`~클래스이름()`)는 객체가 사라질 때 자동 호출되며, 매개변수도 오버로딩도 없다.
